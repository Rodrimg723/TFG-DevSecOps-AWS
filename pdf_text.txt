Objetivos generales y específicos
Objetivo general
El objetivo principal es diseñar, implementar y documentar 
una infraestructura de Alta Disponibilidad y Seguridad en 
Amazon Web Services (AWS), utilizando exclusivamente 
código para su definición y configuración, demostrando la 
capacidad de recuperación ante desastres y ataques.
Objetivos específicos
IaC (Terraform): Eliminar configuración manual. 
Automatización (Ansible): Servidores idénticos siempre. 
Contenedores (Docker): Aislamiento de servicios web.
Seguridad IPS (CrowdSec): Bloqueo en tiempo real.
Monitorización (Grafana): Visualización del estado.

Requisitos funcionales y técnicos
● Hardware Virtual: Instancia EC2 `t2.small` (1 vCPU, 2GB RAM) con Ubuntu 22.04 LTS.
● Conectividad: VPC con subred pública, Internet Gateway y Security Groups restrictivos.
● Web: Acceso HTTPS (443) con certificado SSL válido (Let's Encrypt).
● Seguridad: -SSH solo mediante clave pública (sin contraseña).
-Bloqueo automático de IPs tras 3 intentos fallidos de login o detección de escáneres web.

--- Page 13 ---
Tecnologías seleccionadas
Nube: Se eligió AWS frente a Azure o Google Cloud por ser el líder del 
mercado y por la disponibilidad de créditos educativos (AWS 
Academy).
IaC: Se prefirió Terraform sobre CloudFormation (nativo de AWS) por 
ser agnóstico del proveedor, lo que permitiría migrar a otra nube con 
cambios menores.
Configuración: Se optó por Ansible en lugar de Puppet o Chef por ser
"agentless" (no requiere instalar un agente en el servidor destino) y por 
su menor curva de aprendizaje al usar YAML.
Orquestación: Se optó por Docker Compose en lugar de Kubernetes
(K8s) debido a la complejidad y costes de K8s para un proyecto 
unipersonal, siendo Docker suficiente para gestionar 5-10 contenedores.

Arquitectura General
AWS: Security Group restrictivo.

Docker: Contenedores aislados. Traefik como única puerta de entrada.

--- Page 17 ---
Diagrama Lógico
Entrada Perimetral: Una petición llega de Internet 
y atraviesa los firewalls base (AWS SG + UFW) 
hacia el puerto 443.
Recepción y Consulta: El proxy Traefik recibe la 
petición web. Antes de redirigirla a la aplicación 
objetivo, el "Bouncer" entra en acción.

--- Page 18 ---
Diagrama Lógico
 Detección Activa: CrowdSec, que analiza 
constantemente los logs de Traefik, detecta el 
comportamiento anómalo y las firmas maliciosas 
de la petición.
Bloqueo Efectivo: CrowdSec añade la IP del 
atacante a su lista negra. El Bouncer ordena a 
Traefik denegar el acceso instantáneamente (Error 
403 Forbidden) protegiendo la app.
Monitorización: Todo el incidente de seguridad es 
recolectado por Prometheus y se refleja 
visualmente en los paneles de Grafana.

--- Page 19 ---
Interfaz
Traefik Dashboard: Visibilidad del enrutado en tiempo real.
Grafana: Monitorización centralizada (recursos y seguridad).

--- Page 20 ---
Usabilidad
Para el Administrador: Gestión 100% visual y 
centralizada. No hace falta entrar por consola (SSH) para 
ver el estado del sistema; todo se supervisa mediante 
entornos web (Grafana y Traefik).
Para el Usuario Final: Navegación transparente con 
certificados SSL (Let's Encrypt) auto-renovables. Evita por 
completo los mensajes de "Sitio no seguro" en el 
navegador.
Para el Despliegue: Usabilidad basada en la simplicidad. 
Toda la complejidad queda oculta tras la ejecución 
automatizada de Ansible y Terraform.

Dificultades y Soluciones
Permisos Docker en Ansible: Añadido usuario `ubuntu` al grupo `docker`.
AWS ACADEMY: Constante actualización de las credenciales de AWS Academy al iniciar de nuevo el entorno
Certificados de Seguridad: Evitamos que el sistema nos bloqueara guardando los certificados, en lugar de generar 
uno nuevo en cada prueba.
Direcciones IP cambiantes: Automatizamos el código para que detectara la nueva "dirección" del servidor cada vez que este se 
reiniciaba.
Bloqueos del sistema: Se aprendió a desbloquear manualmente la infraestructura cuando el programa se quedaba "congelado" 
por cortes inesperados.
Problemas de permisos: Automatizamos la entrega de permisos al servidor para que pudiera instalar las aplicaciones sin dar 
errores de acceso.
Desconexiones del entorno educativo: Al usar cuentas que caducan rápido, implementamos una rutina para renovar las 
contraseñas antes de cada uso.
